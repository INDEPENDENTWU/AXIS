- change class: `product-ui`

This slice converges four user-visible issues without creating another truth owner:

1. **Atomic record-save presentation.** After a factual Encounter is committed, the recorder resets locally but Home no longer renders the short-lived committed-but-not-yet-Active intermediate screen. Existing v82 Active admission settles first, then one render presents the truthful next state. The old floating saving pill is retired; save feedback remains local to the button and the undo strip stays dock-safe.
2. **Executable Flow start.** `開始此項` now follows one explicit rule: ongoing modes (`sets`, `rounds`, `timed`, `hold`) enter the existing v82/v87 Active lifecycle immediately; one-shot modes use the canonical recorder because the record itself is their completion fact. A foreign Active item is paused/preserved through the existing switch coordination instead of being overwritten.
3. **Kinetic set cue.** The Production-sealed 8.25.1 inline fact-row morph remains factual authority. 8.26 adds one small, pointer-inert, non-layout `+1 組` kinetic cue at the safe edge of the existing Active stage after a real set completion. It has reduced-motion behavior and may not intersect the clock, controls, Capture dock or navigation.
4. **Quieter Home hierarchy.** Duplicate Active summary copy/compact metric blocks and redundant full-width separators are retired while the unique whole-session end control remains physically reachable. Hierarchy is carried by typography, spacing and bounded tonal grouping rather than repeated cards and rules.

No Session writer, Encounter writer, Active lifecycle owner, recorder, storage namespace/database, network owner, AI owner or historical rewrite is added.
