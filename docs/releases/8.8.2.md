# AXIS 8.8.2 Release Log

Status: release candidate until the exact branch head passes Chromium, iPhone/WebKit, full product matrix and fixed Production verification.

## Purpose

AXIS 8.8.2 makes the first-layer Today experience reflect the user's real training state, strengthens local camera memory without requiring AI, turns Quick Record into a genuinely reusable personal entry point, expands the exercise/anatomy catalog, removes active-card geometry instability and makes automatic sound semantics unambiguous.

## User-visible changes

### Home / “现在”

The Today page has one canonical `#axisNowHero` driven by one `app.js` state model. It distinguishes:

- first use / ready;
- between-session recovery;
- reasonable time to train again;
- unusually long break between sessions;
- session started but no item recorded yet;
- active item;
- active item paused;
- set rest, with elapsed rest and recommended rest threshold;
- rest slightly beyond the threshold;
- rest substantially beyond the threshold;
- item completed and waiting for the next item.

The model uses current activity metadata, set completion, pause timestamps, item estimates, recent training gaps and configured/historical rest timing. The floating current-item card, photo-record action, Quick Record action and bottom navigation remain separate and are not redesigned by this release.

The new visual system uses a large tabular state/time value, a compact progress dial, a two-point fact line and one progress rail. Static CSS owns geometry; the 1-second home tick only mutates text, data-mode and progress values.

### Personal Visual Memory — no AI required

The existing local image fingerprint memory is upgraded from one whole-frame hash / nearest sample to three local signals:

- whole-frame dHash;
- center-region dHash;
- 4 × 4 luminance-zone signature.

AXIS stores multiple confirmed samples per equipment and ranks candidates using multi-signal distance plus the margin to the second-best candidate. A strong match is presented as `本地认出`; a weaker useful match is presented as `本地候选 · 请确认`.

This path is local and network-independent. It is intentionally a **personal repeated-equipment recognizer**, not a semantic vision model: it can become useful for equipment the user has previously confirmed, especially in the same gym and from reasonably similar views. It does not claim reliable identification of completely unseen equipment without AI.

### Quick Record

Quick Record now has a dedicated `我的` section containing the user's saved custom equipment / movements, sorted by recent use when possible.

A Quick Record editor can attach media without abandoning the draft:

- `补拍照片`;
- `3秒视频`;
- `5秒视频`.

Media capture reuses the existing `app.js` camera, watermark and IndexedDB persistence transaction through `window.__AXIS_CAPTURE__`. No second media store or second record writer is introduced. Explicit 3/5-second capture is preserved even when the general “keep clip” preference is off, because the user explicitly requested the clip.

### Exercise / anatomy coverage

New canonical muscle cores include:

- 腰部;
- 前臂;
- 内收肌;
- 髋屈肌;
- 胫骨前肌;
- 前锯肌.

The professional editor adds an explicit `腰` region with lumbar details including 腰方肌、竖脊肌腰段、腰多裂肌 and 髂腰肌.

Non-duplicate movement additions include 45°罗马椅背伸、反向挺身、绳索/哑铃侧屈、鸟狗式、死虫式、绳索伐木、钟摆深蹲、腰带深蹲、北欧腿弯举、臀腿挺身、西西深蹲、胫骨前肌提拉、腕弯举、反向腕弯举、农夫行走、雪橇推/拉、战绳、药球砸地、跳箱、绳索外旋、俯卧撑加、哥本哈根侧桥、绳索屈髋、地雷杆划船 and 器械直臂下拉.

### Active-item card stability

`v87` remains the single active-session owner. Set completion no longer changes the action row's width-bearing layout: the primary / status / add-set columns keep fixed occupancy, and the outer card has immutable left/width/transform geometry. Browser regression samples transient geometry around set completion rather than checking only the final frame.

### Sound semantics

`v8710-sound-ui.js` remains the canonical sound owner. Automatic training cues are now restricted to exactly one condition:

> an active item's normalized countdown naturally reaches zero while the item is still active.

The following automatic cues are retired:

- tapping `完成一组`;
- motion-triggered set completion;
- long-press manual item finish;
- automatic rest-threshold cue;
- session-duration cue.

Manual sound preview in Settings remains available because it is an explicit user action.

## Retired behavior

- The old `liveSignalWrap` / `idleSignalWrap` “现在/最近” presentation is no longer a visible state owner.
- Quick Record no longer depends on “recently used” as the only way for saved custom items to appear.
- One whole-frame perceptual hash is no longer sufficient by itself to assert a local recognition.
- Set completion / manual item finish / rest threshold / session target may not emit automatic AXIS sound.
- Set completion may not change the active-card outer geometry.

## Known limitations

- Personal Visual Memory is intentionally not general semantic object recognition. A completely new unseen machine still needs AI or manual confirmation.
- Similar machines photographed from dramatically different views can remain ambiguous until the user confirms more samples.
- Browser camera / MediaRecorder format support still depends on the platform. Existing graceful fallback behavior remains required.

## Release-candidate engineering validation

The first full release-candidate pass surfaced several lifecycle and cross-browser issues that were repaired without adding competing runtime owners.

### Quick Record first-paint lifecycle

The first-paint shell already contained `#quickRecordBtn`. Historical `v61.js` installation treated “button node exists” as equivalent to “Quick Record interaction is installed” and returned early, which could leave a visible button with no handler or sheet after a cold boot or page restore.

8.8.2 changed this to an idempotent ownership contract:

- the shell may own the prepaint button node;
- `v61.js` always owns interaction installation;
- sheet, handlers and the `我的` section are ensured independently of node pre-existence;
- the owner mounts eagerly during module execution and self-heals on `pageshow`;
- `window.__AXIS_QUICK_READY__` exposes real interaction readiness;
- the build rejects a return-to-early-on-existing-button implementation.

This repaired repeated cold boot and iPhone/WebKit page-restore behavior without adding a second Quick Record owner.

### Browser test-contract convergence

Several old browser assertions no longer represented the product's canonical interaction model. They were corrected rather than reintroducing retired UI:

- the hidden historical `#startBtn` is not a user entry; capture / Quick Record plus first save starts a session;
- the current active item pauses and resumes through the same `#v87Toggle`; the secondary paused list is not the current-item resume owner;
- equipment confirmation uses the visible `v8710` live-catalog search result, not the hidden legacy `[data-eq]` list;
- rest/session automatic reminder controls are required to remain hidden/retired; the product matrix now persists the canonical item-countdown reminder setting instead;
- WebKit pause/resume waits for the canonical persisted `paused` / `active` state plus its visible glyph rather than relying on an arbitrary 90 ms delay.

The full product matrix was explicitly restored and preserved after this correction. Only the obsolete rest/session sound expectation was replaced; navigation, profile, custom equipment, capture preferences, watermark, storage, Quick Record numeric editing, set-count changes, active-item pause/resume, set completion, canonical adjustment, history, v84 trends and canonical v8710 report coverage remain release-blocking.

### WebKit photo-save failure and canonical Media Store

A real iPhone/WebKit failure was reproduced in the 8.8.2 local-vision flow: after a photo was uploaded and `高位下拉` was confirmed, `saveScan()` stayed open and displayed `保存失败`. At the failure point no event had been committed and no local visual memory sample had been learned. The caught IndexedDB transaction error was `null`, exposing a WebKit-sensitive persistence path rather than a UI timing problem.

The repair converged media persistence instead of adding a browser-specific fallback:

- `app.js` is now the sole direct owner of the `axis_v42_media` IndexedDB database;
- Blob writes are encoded as a stable `ArrayBuffer` structured-clone envelope (`axis-media-arraybuffer-v1`);
- reads reconstruct a Blob and remain compatible with historical records that were stored directly as Blob values;
- `v61.js` media deletion delegates to `window.__AXIS_MEDIA_STORE__`;
- `v877-runtime.js` media get/put delegates to the same store;
- `v8710-watermark.js` media get/put delegates to the same store;
- the build scans direct `indexedDB.open(DB,1)` owners and fails unless `app.js` is the only one.

This is a cross-browser storage hardening change, not an iPhone-only conditional. The same canonical Media Store is used by normal capture, Quick Record media attachment and watermark restamping.

## Durable release-log rule

Starting with 8.8.2, every product iteration or repair must leave a durable release log before merge. The log must state user-visible behavior, rationale, owner changes, retired behavior, regression gates and known limitations. The authoritative deployed source SHA remains `axis-build.json.sourceCommit` on the fixed Production URL; the merge and deployment records must match it before a release is marked complete.
