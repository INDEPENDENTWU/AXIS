# AXIS Product Convergence Plan

This document is **post-seal planning**, not authority to expand the current corrective release.

## Product north star

AXIS should evolve from a workout-tracking application into **human-performance execution and evidence infrastructure**.

The durable product spine is:

**Intent → Execution → Evidence → Evolution**

The corresponding domain chain is:

**Object → Protocol / Flow → Runtime → Encounter → Evidence → Evolution**

Reality remains authoritative. AI may observe, infer and recommend, but it does not silently rewrite factual execution or human decisions.

## Ordered program after Production Integrity

1. **Product Convergence** — unify capability language, semantic UI state and capability-oriented contracts; reduce version-oriented presentation debt without rewriting the product.
2. **Domain Runtime** — move platform-neutral decisions toward events → reducer → state → projection → decisions using bounded strangler migration.
3. **Event + Evidence Provenance** — preserve source, encounter, device, artifact and decision lineage without creating a second history.
4. **AXIS Workspace** — organization, people, protocols, assignments, exceptions, evidence and review surfaces separated from the quiet participant execution shell.
5. **Enterprise Foundation** — identity, multi-tenancy, RBAC, cloud sync, audit, API, webhooks, retention/deletion controls and operational observability.
6. **Bounded Intelligence** — observed / inferred / recommended / decided remain distinct; recommendations carry model/input/reason/confidence provenance and require explicit human acceptance when they change protocol intent.
7. **Protocol Runtime SDK** — portable Object, Protocol, evidence requirement and completion contracts that third-party products can execute through AXIS Runtime.
8. **Enterprise Pilot** — validate with a small number of coach, studio or performance-organization workflows before broad feature expansion.
9. **Scale** — integrations, compliance/security hardening, OEM/API licensing and operational scale only after real pilot demand.

## Design rule

Geometry is product state. A state transition may not introduce unexplained layout movement, duplicate semantic owners, decorative residue or hidden interaction cost. Critical running, paused, complete, review, save, error, offline and unavailable states require explicit geometry and ownership contracts.

## Commercial positioning to preserve

Do not compete primarily as a generic AI fitness coach. The differentiated enterprise proposition is the **execution truth layer** between intended protocol and what actually happened:

**Protocol → Assignment → Execution → Encounter → Observation → Evidence → Deviation → Outcome → Recommendation → Human Decision → Next Protocol Version**

Near-term commercial entry should favor coaches, studios and performance organizations where prescribed-vs-performed execution and evidence are operational problems. Long-term leverage may come from Workspace plus Runtime/API/SDK licensing.

## Current boundary

None of this program begins until the current Production Integrity corrective release is fully certified and governance-sealed. The active release must remain bounded to its stated defect and ownership boundary.
